# V4/F3/CIRCEv2 source cleanup — 2026-09-28

## Result

The maintained implementation now has three selectable pipelines: **V4
(default), F3, and CIRCEv2**. V4 is the original dictionary-free model used in
the recent case studies. The workspace and implementation repositories are on
`research/v4-f3-circev2-cleanup-20260928`; changes are in the working trees and
have not been pushed.

The old layout mixed reusable model loading with campaign launchers, semantic
dictionary experiments, and abandoned architecture variants. The new
`horizyn/pipelines` API centralizes loading, fusion, residual refinement,
training-feature export, training, inference, and metric evaluation. Case-study
runners use those shared helpers. The large neural model file is split by
responsibility under `horizyn/models`, preserving the historical
`horizyn.model` import path and class names for checkpoint compatibility.

## Active layout

| Location | Responsibility |
|---|---|
| `horizyn/pipelines/registry.py` | Only V4, F3, CIRCEv2; reject unrelated architectures |
| `pipelines/checkpoints.py` | CPU-staged encoder loading and authenticated residual heads |
| `pipelines/fusion.py`, `scoring.py` | One V4 fusion/refinement/scoring implementation |
| `pipelines/training.py` | Shared encoder training engine, concise recipe logging |
| `pipelines/export.py`, `refinement.py` | Training-only vectors/edges and V4 phase 2 |
| `pipelines/inference.py`, `evaluation.py`, `cli.py` | Independent encoders, official metric functions, common commands |
| `horizyn/models/{common,enzyme,reaction,dual}.py` | Neural layers and modality-specific responsibilities |
| `horizyn/models/compat.py` | Inactive historical constructor dependencies |
| `configs/pipelines/` | Explicit dataset-specific V4 profiles and historical F3/CIRCEv2 profiles |
| `tests/fixtures/` | Reusable real-feature training fixture |
| `archive/20260928/` | Historical source/config/test/documentation records |

`train.py` and the residue-training script delegate to the shared trainer.
Three old campaign filenames retain small import shims for historical helper
imports. Their full experiment implementations are archived. Feature
extractors and the annotation-negative pool builder remain active utilities.

archived rather than discarded because saved experiment reports refer to it.

readable-source snapshot and preexisting Git diffs were captured before edits.

Datasets, learned checkpoints, pretrained feature/scorer weights, existing
feature caches, run configs and source snapshots, evaluation results, and
manuscripts remain at their original paths. Third-party baseline repositories
remain available for scientific comparisons. Preexisting user changes were
preserved. Root data-preparation utilities remain alongside their datasets.

This cleanup changes code organization and entry points. It is not a new
training campaign or a claim of improved benchmark/generalization performance.

The subsequent [output artifact cleanup](ARTIFACT_CLEANUP_20260928.md)
removed stale search scratch, historical candidate-embedding caches, bytecode,
and two incomplete feature writes. Completed features, checkpoints, and
scientific results were preserved; see that report for the deletion manifest.

## Compatibility and verification

- All 32 top-level neural class/function definitions from the original
  `model.py` have identical ASTs after extraction into the new modules.
  Parameter names, layer structure, defaults, and arithmetic were preserved.
- The final V4 encoder/refiner reproduces all eight saved Rv1430 scores with
  **zero absolute difference** and the identical ranking. Reaction and enzyme
  embeddings also match the pre-split shared-API outputs exactly.
- The real F3 epoch-99 and CIRCEv2 epoch-23 checkpoints load successfully.
  All four frozen V4 manifests use the same fitted artifacts and validated
  head/feature lineage. The EnzymeMap calibrated checkpoint uses multiplier
  1, retaining half the trained residual coefficient.
- Shared-core tests exercise actual optimizer steps, checkpoint reload,
  positive-graph semantics, attention regularization, validation parity,
  resume/recovery, official retrieval metrics, and feature readers.
- New API tests exercise fusion arithmetic, whole-bank screening evaluation,
  all-positive ReactZyme MRR, artifact/lineage rejection, training-only graph
  fitting, and a real V4 checkpoint → feature export → residual fitting path.
- The dependency audit verifies that maintained local imports resolve.

Initial test failures identified a fixture that moved with its historical
experiment. The reusable fixture now lives under `tests/fixtures`, and the
validation tests reference it there. The final suite reports **873 passed** in 36.84 seconds, with 39 existing
dependency/Lightning runtime warnings. Its output is recorded in
`pytest_final.log` in the evidence directory.
